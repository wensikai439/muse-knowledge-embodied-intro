# Muse 的知识库积累（具身入门）

Mark 的具身智能入门个人知识库。

> **铁规：没有 Mark 亲自批准，什么都不往这个仓库里放。**
> 对话里出现的资料、链接、论文、文件，只有 Mark 指名说“放进知识库”才入库。墨奇不自行挑选、不自行搬运。

这是一个公开仓库（Public）。不要放密码、密钥、验证码、私人账号信息、个人隐私。

## 这个库是给谁的

给刚进入具身领域的小白 Mark 用的：从零开始，先建立地图，再一个一个概念弄懂，最后落到能动手、能评测、能讲清思想。

## 分类逻辑：怎么分的，为什么这样分

不是按来源分（不按“这是哪篇论文、哪个网站来的”），而是按**学习路径 + 机器人干活的闭环**分：

1. **先有地图（01）**：具身智能是什么、由哪几块组成、要学什么、现在做到哪一步。
2. **再有词（02）**：每个词第一次出现就从零定义，不猜、不跳过。这是全库的字典。
3. **再走一遍闭环（03–05）**：机器人干活就是一个循环——
   `感知（03，看见与理解世界）→ 策略与代码（05，决定怎么做、写出 solve()）→ 本体与硬件（04，身体怎么执行）`
   顺序按闭环排，03 在前不是因为它最重要，而是因为它是循环的起点。
4. **再学怎么量、怎么变强（06–07）**：`仿真与评测（06，怎么知道做得好不好）→ 学习与泛化（07，数据、训练、怎么从一个任务泛化到下一个）`。
5. **最后是来源与自己的东西（08–10）**：`论文精读（08，每篇只讲思想）→ 开源项目与工具（09，能直接用的东西）→ 我的实践（10，Mark 自己的任务、实验、问题）`。

一句话记：**地图 → 词 → 感知 → 决策 → 执行 → 评测 → 泛化 → 论文 → 工具 → 我的实践。**

## 文件夹一览

| 文件夹 | 放什么 | 不放什么 |
|---|---|---|
| `00-说明与规则` | 本库规则、入库流程、模板 | 具体知识点 |
| `01-入门地图` | 具身智能全景、路线图、发展史、为什么做 code-as-policy | 单篇论文细节 |
| `02-术语表` | 每个术语从零定义，配一个最简单的例子 | 不加定义的黑话 |
| `03-感知` | 视觉、语言、触觉、状态估计、世界模型、图像差异等“看见与理解” | 决策代码本身 |
| `04-机器人本体与硬件` | 机器人、关节、夹爪、传感器、执行器、运动学/动力学入门 | 仿真器评测方法 |
| `05-策略与代码` | 规划、策略、VLA、code-as-policy、控制、调试循环 | 纯感知模型 |
| `06-仿真与评测` | 仿真器、基准（benchmark）、任务、评分器、harness、评测方法 | 训练配方 |
| `07-学习与泛化` | 数据、轨迹、微调、强化学习、泛化、失败分析 | 单个基准的任务清单 |
| `08-论文精读` | 按 Mark 规矩写的精读：发现了什么问题、关键办法是什么、对我们哪个环节有用、开源吗 | 只抄关键词的摘要 |
| `09-开源项目与工具` | 核实过的开源项目、工具、脚手架，写清能直接用还是只能借思路 | 未核实就推荐的链接 |
| `10-我的实践` | Mark 指定的任务规范、实验记录、复盘、待解决的问题 | 未经 Mark 批准的搬运 |

每个文件夹里都有自己的 `README.md`，写明“放什么 / 不放什么 / 怎么命名”。

## 怎么让墨奇往里放东西

Mark 在对话里说一句就行，例如：

- “把刚才那篇 DeltaTok 的精读放进 08”
- “把转水龙头那个任务规范放进 10”
- “把这个链接放进 09，注明只能借思路”

墨奇只按这句话放，放完在对话里回你放到了哪个文件、文件名是什么。

## 命名规矩

- 文件名用英文小写加 `-`，例如 `delta-tok-idea.md`；标题第一行写中文名。
- 每篇精读 / 每个资料开头写三行：来源、日期、Mark 为什么要收它。
- 不确定的地方写“未核实”，不编、不猜。

## 和 muse-memory 的分工

- `muse-memory`（私人）：墨奇的记忆与工作文件，按账号分。
- 本库（公开）：Mark 的具身入门知识，只放 Mark 批准的公开学习资料。
